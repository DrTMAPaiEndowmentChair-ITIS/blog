A robot policy can be correct about the scene and still move the wrong way. A joint order changed. A camera frame arrived late. A normalized action was decoded with statistics from another dataset. These failures make the experimental setup part of the research result.

NVIDIA's GR00T work is useful to study at this level. It combines a generalist robot policy with a broader ecosystem for simulation, data generation, and adaptation. The scientific question is how those pieces help a policy work under conditions it did not see during training.

## Read a model release as a collection of design choices

GR00T N1.6 uses a Cosmos vision-language backbone and a larger diffusion transformer than its predecessor. Its release describes state-relative action chunks for most embodiments, additional teleoperated data, and task-specific post-training. It also documents unresolved problems in language following and out-of-distribution task generalization.[^n16]

Relative actions deserve attention. A small motion expressed relative to the current state can be convenient across starting poses. It can also accumulate error when the controller repeatedly executes imperfect displacements. The choice changes what a rollout failure means.

The original GR00T N1 paper provides the earlier generalist humanoid foundation-model formulation.[^n1] Treat the N1.6 project as a particular update with its own data and evaluation, rather than carrying every earlier architectural detail forward automatically.

## Synthetic data needs a validity audit

A simulator can produce more trajectories than a human demonstrator. That is useful only if the trajectories preserve the constraints relevant to the downstream task.

For a grasping task, a nominal success can hide an interpenetrating object, an impossible friction setting, or a controller that depends on privileged simulator state. Before asking whether synthetic data improves learning, ask what counts as a usable episode.

Even a valid trajectory can be redundant. A thousand nearly identical grasps may offer less useful variation than a smaller collection spanning object poses, contact conditions, and recoveries. Record the generation procedure and rejection reasons, not only the number of saved episodes.

## Randomization has a geometry

Domain randomization varies simulation parameters so that training covers a range of possible conditions. The important question is whether the range includes the conditions that matter at deployment.

Isaac Lab provides an open framework for robot learning built on Isaac Sim, with environment construction, learning workflows, and configurable simulation components.[^isaac] The framework makes experiments easier to organize, but the research team still chooses the distributions and observations.

## Write down the observation and action contract

A reproducible setup should state camera intrinsics, frame conventions, image preprocessing, state fields, control frequency, action horizon, and the rule for executing or replacing a predicted chunk. Include units for every continuous quantity.

Make the coordinate contract executable with simple checks. A known positive action should move the expected joint in the expected direction. A rendered calibration object should land at the expected image location. A delayed observation should carry its capture timestamp rather than silently becoming the current state.

Preserve normalization statistics with the checkpoint. A model trained with one action scale and evaluated with another has changed its effective controller even when the weight file is identical. The N1.6 release's discussion of pretraining and post-training statistics makes this a particularly relevant replication detail.[^n16]

## A manageable experiment can still be informative

Start with one embodiment, a small set of manipulation tasks, and a fixed adaptation budget. Compare real-only training with a mixture that adds synthetic trajectories while keeping optimization steps and evaluation conditions explicit.

Hold out object instances and starting poses separately. Include disturbed starts and recovery attempts, since an uninterrupted demonstration mainly tests nominal execution. Report completion, interventions, collisions, and elapsed time as separate outcomes. A partial task completed quickly should not be silently counted as full success.

Freeze the simulator, asset, physics, and policy versions. Run multiple seeds and publish episode-level results. A successful simulation run is simulator evidence. Transfer requires trials on the target embodiment under a documented procedure.

NVIDIA's contribution here is the connection between models and an experiment infrastructure. The useful research result is a measured account of which forms of generated experience improve which failures. That account can guide the next dataset or controller change far more reliably than a polished demonstration alone.
